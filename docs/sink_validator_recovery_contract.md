# Sink application-validator rejection recovery

## Scope

The target-selected, hash-pinned acceptor generated by `tools/patch_sink_raw_configuration.py` additionally recovers a **Sink SET_CONFIGURATION rejected by the normalized media validator**. Installed Pico SDK 2.1.1 / BTstack `501e6d2b86e6c92bfb9c390bcf55709938e25ac1` remains unchanged. This is a lifecycle correction, separate from raw-configuration validation.

## Ordering and ownership

1. The existing raw guard runs before unpacking. Its behavior is unchanged by this correction.
2. The SDK temporarily sets endpoint state to CONFIGURATION_SUBSTATEMACHINE and binds it to the requesting connection, exactly as before. The real `avdtp_validate_media_configuration` constructs the normalized event. Public `a2dp_sink_register_media_config_validator` converts/restores its subevent around the application callback.
3. Only if that callback returns a nonzero error for a Sink does the helper restore the prior endpoint state and connection pointer. It returns a private boolean to its caller, preventing the otherwise unconditional REMOTE_INITIATED transition. This helper is internal, not a new public API.
4. Stored codec bytes, local/remote configuration, ownership/in-use fields and unrelated endpoints are not committed on this rejection. The pending endpoint rejection is preserved until normal can-send scheduling. During that pending interval the endpoint's acceptor substate is intentionally the existing reject-pending state, not its pre-command idle state.
5. The reply retains transaction label, SET_CONFIGURATION identifier, MEDIA_CODEC category and the application's error byte. For Sink SET category rejects, response CID/transaction label come from the **requesting connection**, not a restored endpoint owner. The original endpoint dispatch still emits its normal rejection notification after sending: requesting AVDTP CID, local SEID, `is_initiator=false`. The SDK's existing Source/Sink broadcast is retained.
6. After the reject is dispatched, another valid configuration in the same session may be allowed by the application and proceed normally. No automatic retry or second invocation of the validator is added.

Source follows the original helper result and transition behavior; other response routing is unchanged. AVRCP is not modified. Reconfiguration keeps the previously implemented validator behavior; this correction does not add a new RECONFIGURE state transition.

## Public receiver and limits

`SinkProfile::validate` uses its normalized codec checks and callback-side authenticated session/CID. It does not depend on the endpoint argument. Nevertheless this change preserves the SDK's pre-callback temporary owner/state so existing validators see the same ordering. An application decision must be synchronous and must not mutate/free SDK session objects or re-enter dispatch; arbitrary callback side effects are not rolled back.

This is not a general repair of SEP-in-use, remote-SEP conflicts, all AVDTP states, fragmented signaling, concurrent/reentrant commands, transport-send failures or Source lifecycle. Prior endpoint ownership by another connection is restored on veto; that does not authorize successful takeover of an active endpoint. Tests use a non-in-use endpoint for this restoration case.

## Verification

The dedicated validation fixture used only two fixed valid SBC configurations with controlled application decisions, real SDK parsing/normalization/A2DP validator forwarding and stub transport/session allocation. It does not invoke the earlier raw-input suite.

This validator-rejection recovery path has fixed-input host tests and ARM compile/link coverage, not a dedicated radio interoperability trial. This feature-specific limit does not negate the separate bounded shared-code SBC/Sink hardware results.
