# 機能と制約

[English](supported_features.md) / [README](../README_jp.md)

Pico Wのアプリに組み込む前に確認したい、機能の範囲をまとめています。使い始める手順は各サンプル、関数の詳細は[APIリファレンス](api_reference_jp.md)を参照してください。

## 音声の送受信：A2DP

- **Source（送信側）**は、アプリから受け取ったPCMをSBCに圧縮して送信します。
- **Sink（受信側）**は、受信したSBCをPCMに戻し、アプリへ渡します。
- DACやI2Sへの出力、音量の調整などはアプリ側で実装します。Sinkを有効にするだけでPicoから音が鳴るわけではありません。

対応コーデックはSBCです。ほかのコーデックや通話用のHFPは対象外です。

使い方：[音声送信](../examples/A2DPSourcePlayer/README_jp.md) / [PCM受信](../examples/A2dpSinkPcmConsumer/README_jp.md)

## プレーヤーの操作：AVRCP

- **Controller（操作を送る側）**から、再生・一時停止・曲送り・音量ボタンなどの操作を送れます。
- **Target（操作を受ける側）**で受け取った操作は、アプリの処理につなげます。再生状態や音量もアプリ側で管理します。
- 曲情報の取得・通知、Browsing、Cover ArtなどのAPIもありますが、すべてを実機確認済みとしているわけではありません。

相手が命令を受け付けても、意図したプレーヤーが動くとは限りません。アプリでは応答と実際の状態を確認してください。音量ボタンの送信と、絶対音量の設定やPico側の音量調整は別の機能です。

[Sink＋Controllerサンプル](../examples/AvrcpMediaControlSample/README_jp.md)で試せる操作は、一時停止と再生です。曲送り・音量操作を使う場合は[Controller API](avrcp_controller_jp.md)でアプリに追加します。

## データ通信：SPP

シリアル通信と同様にバイト列を送受信できます。同じ相手機器に対して最大2本の通信経路を使えますが、これは2台同時接続の機能ではありません。

メッセージの区切り、受信確認、再送のルールはアプリ側で決めます。詳しくは[SPPの使い方](spp_examples_jp.md)を参照してください。

## 組み合わせて使うとき

A2DP・AVRCP・SPPは共通のBluetooth初期化処理を使います。各機能の処理を、同じメインループから継続して呼び出してください。

音声を受け取るSinkと、操作を送るControllerは併用できます。これは音声を送受信するSource＋Sinkの同時動作とは別です。任意の機能の組み合わせや、すべての相手機器での動作を保証するものではありません。

## 動作確認の範囲

通常のSBC送信と、WindowsからのSBC受信は実機で確認しています。Windowsの音声を受信しながら、曲送りと音量ボタンを操作する試験も行いました。Controllerの一時停止・再生は別の試験で確認しています。

公開版のPCM受信サンプルとSink＋Controllerサンプルは、ビルドとソフトウェア試験で確認していますが、そのアプリ自体の実機確認は未実施です。共有するライブラリの実績が、各サンプルや相手機器での動作を保証するわけではありません。

長時間の連続運転、さまざまな機器との互換性、Wi-Fi併用などは、利用する構成で別途確認してください。試験条件や経緯は、[検証範囲](validation_jp.md)にまとめています。
